# Review — Wi-Fi selection stability and automatic refresh

## Executive Summary

Fixed the Wi-Fi UI crash that occurred when selecting a network and added automatic background rescanning to both Wi-Fi interfaces: the primary setup screen and the standalone picker. Selection no longer rebuilds the active `ListView` while Textual is dispatching its selection event. Repeated scans preserve visible rows during refresh, temporarily disable stale rows, and re-enable them after a ready result arrives.

## Discovery and Baseline

- Scope: `src/portallens/tui/setup.py`, `src/portallens/wifi/picker.py`, and their tests.
- Root cause: selection synchronously published controller state; the renderer cleared and rebuilt the `ListView` during the same Textual selection event.
- Refresh gap: discovery previously ran once on mount, with manual `r` rescans only.
- Final validation: 309 tests passed; Ruff passed; strict mypy passed for 46 source files; `git diff --check` passed.

## Findings and Fixes

### High — selecting a Wi-Fi row could crash the TUI

The setup and standalone picker now rebuild network rows only when display-relevant network data changes. Selection-only state updates leave the current list intact, avoiding DOM mutation during `ListView.Selected` dispatch. Regression tests drive actual keyboard selection for both apps.

### Medium — Wi-Fi lists did not refresh automatically

Both apps now accept a configurable refresh interval (10 seconds by default), start a recurring scan timer when automatic scanning is enabled, skip refresh requests while a scan is active, and stop the timer during unmount. Repeated scans were verified with a controlled Textual harness.

### Medium — stale rows could be selected during a scan

Existing rows remain visible to avoid Textual's asynchronous mount race, but the list is disabled while a replacement scan is in progress or has failed/cancelled. It is re-enabled only after a ready state is rendered.

### Low — lifecycle and test reliability

Status and refresh timers now clear their references when stopped. Tests cover timer cleanup, cancellation, deterministic single-flight UI rescans, real keyboard selection, and a controller-driven scanning-to-ready transition. Async tests use non-blocking polling rather than blocking the Textual event loop.

## Changes Applied

- Added safe rendered-row signatures to both Wi-Fi UIs.
- Added automatic refresh timers and cleanup.
- Added UI-level single-flight guards for manual and automatic rescans.
- Disabled stale network rows during scans.
- Added regression tests for selection, refresh, cancellation, timer cleanup, and callback timing.
- Added a plain-language changelog entry.

## Open Items

The selected Wi-Fi workflow remains intentionally read-only. Host-mediated connection, captive-portal handoff, live SQLite event persistence, and authorized follow-up orchestration remain the next feature slice documented in the existing backlog and ADR-24.

## Recommended Next Step

Attach the existing bounded captive-portal detector to a selected, host-connected Wi-Fi session through the generation-guarded controller, then persist redacted live events while preserving stop/switch controls.
