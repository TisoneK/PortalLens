The 2 pytest failures are pre-existing platform issues — `test_xdg_data_home` and `test_default_under_home` assert POSIX-pathed strings (`"/xdg/portallens/investigations.db"`) and fail on Windows where the code correctly returns `\`-separated paths. ## Findings

### N-1 — Path-separator tests fail on Windows (Low)
- **Description:** `TestDbPathResolution::test_xdg_data_home` and `test_default_under_home` hardcode `/`-separated path strings, which fail on Windows.
- **Impact:** 2 test failures on Windows; reduces developer confidence when running the full suite locally.
- **Recommendation:** Replace literal path strings with `Path("/xdg") / "portallens" / "investigations.db"` or equivalent `os.path.join()` calls. This is a one-line change per test.
- **Status:** Logged in `inefficiencies/log.md`. Not fixed — no feature target for this session; fix is trivial and can be done alongside the first feature work.

### N-2 — `context-sync verify` fails on Windows (Known flaw)
- **Description:** `sha256sum` chokes on CRLF in `MANIFEST.sha256` because Git for Windows checks out with `core.autocrlf` by default.
- **Impact:** Cannot run `context-sync verify` or `status` natively on Windows. Core integrity check requires Python or Git Bash workaround.
- **Recommendation:** Normalize MANIFEST.sha256 to LF in the package repo, or add a Python-based verify fallback in `context-sync`.
- **Status:** Already logged in `memory/flaws/log.md` by this session.
