# Review — Primary setup TUI and user-facing documentation

## Executive Summary

The primary user experience now starts with `portallens` and opens a Textual setup screen. The screen exposes passive/active authorization choices, a URL entry path into the existing live investigation console, read-only Wi-Fi discovery and status monitoring, and a no-Wi-Fi fallback. Public README, tutorial, and changelog text now describe the product for users rather than as a development log.

The selected-Wi-Fi path remains intentionally bounded: it does not yet connect, detect a portal, persist live Wi-Fi events, or launch bypass work. That limitation is stated in the public documentation and remains the next implementation slice.

## Discovery and Baseline

- Project: Python 3.10+, Click CLI, optional Textual TUI, SQLite investigations.
- Existing Wi-Fi adapters are read-only and accept no credentials.
- Existing live investigation console is reused for URL targets; setup remains a presentation/control layer.
- Final validation: 300 tests passed; Ruff passed; strict mypy passed for 46 source files; syntax compilation and `git diff --check` passed.

## Findings and Fixes

### High — selected Wi-Fi is not yet a full investigation

Selection currently starts read-only host-status monitoring only. It does not connect through the operating system, run the captive-portal detector, hand off a portal URL, persist live Wi-Fi events, or invoke authorized probes. This is documented as a future slice rather than represented as completed behavior.

### Medium — monitoring could implicitly authorize active URL work

The setup screen previously allowed URL monitoring to authorize analysis when active checks were not selected. Fixed by requiring both `Enable active checks` and explicit authorization for URL monitoring. Added a regression test.

### Medium — worker shutdown

Status polling now owns a `CancellationToken`, passes it to the adapter, cancels it when monitoring stops or the screen unmounts, and suppresses late UI callbacks. Added a blocking-adapter cancellation regression test.

### Low — documentation command accuracy

Corrected examples that placed `--authorized` before a URL without the explicit `analyze` subcommand. Public changelog wording was simplified, and developer-facing Wi-Fi orchestration language was removed from the quick-start documentation.

## Changes Applied

- Added the main `PortalLensSetupApp` and setup result model.
- Bare `portallens` now launches setup; explicit subcommands remain available.
- Added no-Wi-Fi setup fallback and URL validation.
- Added setup tests for scanning, selection, authorization, URL validation, bare launch, no-Wi-Fi fallback, and cancellation.
- Updated README, tutorial, and changelog for non-technical users.
