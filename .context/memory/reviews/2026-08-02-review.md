# Review — Captive-Portal Bypass Detection

## Executive Summary

Implemented five bounded captive-portal bypass detection methods: CONNECT, DNS tunnel, click-through, port reachability, and navigation-parameter tampering. Each method returns typed `Evidence`, requires the existing single `AcquisitionPolicy.authorized` flag, and avoids credentials, authentication, exploit payloads, and application-state changes. Added report-level `detect_bypass()` and immutable `merge_bypass_evidence()` helpers that produce qualified `SecurityFinding` records from positive evidence.

## Discovery Phase

- Reused `Evidence` / `EvidenceType`, `PortalReport`, `SecurityFinding`, and the existing security package export conventions.
- Preserved the passive-by-default architecture and ADR-15 single authorization model.
- Used injectable request, resolver, CONNECT, and port-probe callables so tests never contact live targets.

## Baseline Health

- Baseline before changes: 199 tests passing.
- Final validation: Ruff clean, strict mypy clean across 36 source files, 220 tests passing, `git diff --check` clean.

## Findings

### Medium — verification fidelity is intentionally qualified

A positive probe observes a condition consistent with bypass, not unrestricted access. Findings therefore use potential/provisional language and cite evidence. CONNECT, DNS, click-through, and parameter mutation require independent verification; an open port is only informational prerequisite evidence.

### Low — caller-driven report integration

The passive analyzer does not run active bypass probes. Callers explicitly run authorized probes and invoke `merge_bypass_evidence(report, evidence)` or `detect_bypass(report)`. This preserves the existing passive default and is documented in README and architecture docs.

## Fixes Applied

- Added `BYPASS_CONNECT`, `BYPASS_DNS`, `BYPASS_CLICK_THROUGH`, `BYPASS_PORT`, and `BYPASS_PARAMETER` evidence types.
- Added `security/bypass.py` with bounded defaults, host/port validation, safe navigation-parameter allow-listing, sensitive-parameter refusal, and injectable network seams.
- Added `security/bypass_detection.py` with five evidence-to-finding rules and immutable merge support.
- Exported the public probe and detector API from `portallens.security`.
- Added 21 focused tests covering authorization, positive/negative/inconclusive evidence, bounds, sensitive parameters, all detector mappings, and immutability.
- Updated README, architecture documentation, and changelog.

## Open Items

- Protocol-level verification can be strengthened later with caller-supplied response markers/body checks for click-through and controlled redirect-chain capture. No blocker for this bounded MVP.
- CLI orchestration for explicitly selecting individual bypass probes remains a future UX slice; the library API is complete and safe to compose today.

## Recommended Next Steps

1. Add a CLI command or investigation step registry entries for running selected bypass probes under `--authorized`.
2. Persist probe runs and their audit metadata in `Investigation`.
3. Add controlled fixture captures for redirect-chain and gateway DNS behavior to calibrate confidence.
