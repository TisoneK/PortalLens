- [ ] **ARP-based network enumeration** (added 2026-08-02 by Buffy / Session 14; spec-only) — for an observed gateway IP, enumerate IPv4 hosts on its /24 via ARP requests. **Spec-only first, no implementation.** Active. Bounded defaults (`--count`, `--timeout`, source-IP pinned to the calling interface). Spec rationale: ARP probing is observable on managed switches via MAC-Flap telemetry and is the canonical precursor to any L2 MAC-impersonation technique — build it because you intend to use it, not as an open-ended scanner. Until a future per-action ADR explicitly accepts both ARP enumeration *and* (if approved) MAC impersonation together with explicit scope (`--lab-only` + a target-allowlist + a state-rollback guarantee), this item stays spec-only.

- [ ] **Per-action ADR-16 review: default-credential authentication** (added 2026-08-02 by Buffy / Session 14; ADR required before any code) — write an ADR (not code) assessing whether a probe that authenticates with known-default credentials (e.g. `admin:admin`, `root:`) against a discovered gateway admin interface is acceptable behind `--authorized` under ADR-16. **ADR-18 explicitly forbids** "probe methods ... authenticate, submit credentials"; ADR-16 names "authenticating to a reachable admin panel" as the canonical exploit action requiring per-action assessment. The ADR must either (a) accept with strict per-target scope + rate limits + audit trail + a hard ban on credential persistence across targets, or (b) refuse and explicitly disavow the capability. Until this ADR is accepted, no code may be written that authenticates with credentials against any discovered service. Read-through: this also covers SNMP community-string probing (separate item above) by reframing it: "send a community string" is authenticate-with-credential.

- [ ] **Per-action ADR-16 review: L2 MAC impersonation** (added 2026-08-02 by Buffy / Session 14; ADR required before any code) — write an ADR (not code) assessing whether MAC address spoofing (changing the L2 source address of the calling interface to impersonate another associated client) is acceptable behind `--authorized` under ADR-16. **Qualitative difference from probe-based bypass tests:** this affects the forwarding table of every switch/bridge the operator's network passes through (potential MAC-Flap storm on managed gear) and is itself a credential-impersonation attack on RADIUS / 802.1X. ADR-18's "never attempt to obtain access" applies; ADR-12's bounded-business-intelligence bound also applies (MAC-station correlation can become org-profiling). The ADR must either (a) accept with strict scope (`--lab-only` + hardcoded test-bSSID allowlist + state-rollback guarantee + a `dry-run` default), or (b) refuse and explicitly disavow. Until this ADR is accepted, no MAC-spoofing code may be written.
